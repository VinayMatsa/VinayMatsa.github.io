Licensing basics for flows

VM Vinay Matsa 21 November 2026 3 min read

Licensing decides which connectors a flow may use and how many requests it gets each day. You don't need to know every plan, but a builder should be able to answer: can this flow run on what we have, and who needs a licence? Prices and plan names change, so treat this page as the concepts and check Microsoft's licensing pages for the current details.

The main licence types

LicenceWho or what it coversKey points
Microsoft 365 (seeded)Users with Microsoft 365 or Office 365Cloud flows with standard connectors only, such as SharePoint, Outlook and Teams
Power Automate PremiumOne user, all of their flowsPremium connectors, custom connectors, Dataverse, desktop flows (attended RPA) and more
Power Automate ProcessOne flow (or one machine for unattended RPA)Licenses the flow itself, so everyone who uses it is covered. Higher daily request allowance; licences can be stacked.
TrialOne user, for a limited timeLets you build and test premium features before buying

What makes a flow premium

A flow is premium if it uses any premium connector (Dataverse, HTTP, SQL Server and many others), a custom connector, or features such as desktop flows. The designer marks premium connectors with a diamond label. One premium action is enough to make the whole flow premium.

Whose licence counts

  • Automated and scheduled flows run under the owner's licence.
  • Instant flows (a button or a Power Apps call) generally need the person who runs them to be licensed for what the flow uses, unless the flow has a Process licence.
  • A flow that runs as part of a licensed Power Apps or Dynamics 365 app can be covered by that app's licence when it serves that app.

Per user or per flow?

SituationUsually fits
One maker building many personal or team automationsPremium per user
One business-critical flow used by many people, or a high-volume integrationProcess per flow
Simple notifications and approvals on SharePoint and OutlookMicrosoft 365 seeded licence may be enough
New to this? Start from the basics optional

Standard connector: included with Microsoft 365 licences.

Premium connector: needs a standalone Power Automate (or qualifying Power Apps / Dynamics 365) licence.

Owner: the account a flow belongs to. Automated flows use its licence and its request allowance.

AI Builder capacity and desktop flows

AI Builder (document processing, prompts, text recognition) is licensed by capacity, not by user. Building and testing models doesn't use credits; running them in flows does. Microsoft is ending AI Builder credits: since November 2025, AI Builder features can use Copilot Credits when no AI Builder credits are left, and the credits that came with premium licences are being removed. Check the capacity page in the admin center before relying on AI steps in production.

Desktop flows (RPA): the Premium user licence covers attended desktop flows, which run while the user is signed in. Running desktop flows unattended needs Process licences (or pay-as-you-go).

Common mistakes

  • Building with a trial and discovering at go-live that users only have Microsoft 365 licences.
  • Adding one HTTP or Dataverse action to a standard flow without noticing it is now premium.
  • Running every production flow under one employee's account. Licence, allowance and access all leave with that person. Level 6 covers service accounts.
