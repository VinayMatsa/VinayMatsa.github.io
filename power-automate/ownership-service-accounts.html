Flow ownership and service accounts

VM Vinay Matsa 21 November 2026 3 min read

Every flow has an owner. Automated and scheduled flows run with the owner's licence and request allowance, and their connections usually belong to the owner as well. If that person leaves and their account is disabled, the flow can stop. Planning ownership is part of moving a flow to production.

Owners, co-owners and run-only users

RoleCan do
OwnerEverything. Created the flow, or was made owner later.
Co-ownerAlmost everything: edit, view run history, change settings, manage connections, add owners. Can't remove the original creator.
Run-only userStart an instant flow, using either their own connections or ones the owner provides

Changing the owner

For a solution-aware flow, an owner, co-owner or admin can change the owner from the flow's Details > Edit. Microsoft's guidance adds that the flow uses the plan of its owner, and if the original owner leaves the organisation, the flow drops to the Low performance profile. That is another reason to move production flows to a dedicated owner.

Options for production

OptionGood forWatch out for
Service account (a dedicated user account)Most teams. Licensed like a user, owns flows and connections.Needs a licence, a protected password and a named person responsible for it.
Service principal (an application user)Solution flows that must not depend on any personCan't be a co-owner, and some connectors don't support it.
Individual maker with co-ownersSmall team flowsStill stops if the owner's connections break.
New to this? Start from the basics optional

Orphaned flow: a flow whose owner no longer has a valid account. Admins can find these and assign new owners.

Service principal: an app identity in Microsoft Entra ID, added to an environment as an application user.

Build it step by step optional
  1. Agree who owns production flows: a service account or an application user.
  2. Always build production flows inside solutions, so ownership can be changed.
  3. On import, set each connection reference to a connection owned by that account.
  4. Change the flow owner under Details > Edit, and add a support team as co-owners.
  5. Write down who to contact for each flow, in the solution description or a team page.

Common mistakes

  • A critical flow owned by one person with no co-owners.
  • Changing the owner but leaving the connections on the old person's account.
  • Sharing the service account password widely instead of controlling it.
