Deploying with pipelines

VM Vinay Matsa 21 November 2026 3 min read

Exporting a zip file and importing it by hand works, but it is easy to deploy the wrong version, skip a test stage or forget a variable. Pipelines in Power Platform automate that path. An admin or maker sets up the stages once; after that, deploying is choosing a solution and pressing Deploy.

How a pipeline is built

PartWhat it is
Development environmentWhere the unmanaged solution is built. Deployments start here.
StagesThe targets in order, for example Test, then Production
Host environmentStores the pipeline setup, permissions and deployment history
RunOne deployment of one solution version to one stage, deployed as managed

Two ways to host

  • Platform host: the default, tenant-wide host. Makers can create personal pipelines to environments they can already import into.
  • Custom host: an environment an admin sets up to govern pipelines centrally, with approvals and extensions.

Per Microsoft's documentation, all environments in a pipeline need a Dataverse database, and target environments must be managed environments.

What pipelines check for you

  • The solution is validated against the target before it is deployed.
  • Connection references and environment variable values are asked for up front, so the flows can be turned on straight away.
  • Deployments can be scheduled, and every run is kept in history, with deployment notes that Copilot can draft.

This page has no screenshots, because a pipeline view shows real environment names. The steps below follow the Microsoft Learn guide.

New to this? Start from the basics optional

Managed environment: an environment with extra governance features switched on, such as sharing limits, usage insights and pipelines.

Stage: one step in the path to production, tied to a target environment.

Build it step by step optional
  1. Open your solution in the development environment and select Pipelines on the left.
  2. If there is no pipeline yet, create one and add the target stages (for example Test and Production).
  3. Select Deploy here on the next stage.
  4. Review the validation results, set connections for each connection reference, and enter environment variable values.
  5. Deploy, then test in the target before deploying to the next stage.

Common mistakes

  • Skipping the test stage because the change is small.
  • Editing the deployed managed solution in the target. Fix it in development and deploy again.
  • Forgetting to increase the solution version, which makes the history hard to follow.
