Deploying solutions with PAC CLI: Dev to Stage to Prod

VM Vinay Matsa 10 November 2026 2 min read

Manual export and import works once. For repeatable, controlled releases, the Power Platform CLI (pac) turns deployments into scripts you can run the same way every time.

Start from the root

A solution is the package that carries your apps, flows and tables between environments. Dev is where you build, Test/Stage is where you check, Prod is where people work. Deploying means exporting from one and importing into the next, with the right settings for each. Doing that by hand invites mistakes; a script does it the same way every time.

The walkthrough

  1. Authentication profiles: interactive sign-in for local work; a service principal or workload identity federation for pipelines. pac auth create, then pac auth select to switch.
  2. Set the version and publish: pac solution version or set it before export, so every build is identifiable.
  3. Export both managed and unmanaged: unmanaged for source control, managed for Test and Prod.
  4. Deployment settings file: pac solution create-settings generates a template for environment variables and connection references.
  5. Import to Test with --settings-file and --stage-and-upgrade.
  6. Stage for upgrade in Prod: import as a holding solution, migrate and validate data, then apply the upgrade.

Key points

  • The settings file is a template: fill in every value for each target environment.
  • A ConnectionId must come from the target environment.
  • Applying an upgrade removes components that aren't in the new version. Migrate and check data first.
  • --activate-plugins turns on flows and plug-ins, but verify each flow is on and working.
  • Stop at the first failed step; don't push on and leave environments half-updated.

Pipelines or PAC CLI?

Power Platform pipelines give makers guided, one-click deployments. PAC CLI gives full control in scripts and CI/CD. Both have a place in a healthy ALM strategy. The source control and CI/CD pages in the Learn section go further.
