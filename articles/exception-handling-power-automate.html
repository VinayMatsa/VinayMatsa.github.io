Exception handling in Power Automate: the deep dive

VM Vinay Matsa 29 April 2026 2 min read

Without proper error handling, flows leave processes half-finished, cause failures in other systems, show Succeeded when something important failed, and cost hours of manual recovery.

Start from the root

Exception handling is a plan for what happens when something goes wrong during a run: catch the error, respond to it, and tell someone. In Power Automate there's no try/catch keyword; you build the same idea from scopes and the Configure run after setting.

The building blocks

BlockRole
Try scopeHolds the main actions that might fail.
Catch scopeRuns only when Try failed or timed out (run after: has failed, has timed out).
Finally scopeRuns whatever happened (run after: all four outcomes).
TerminateEnds the run with the right status (Failed, with your message).
Retry policyRecovers automatically from temporary failures; fixed or exponential intervals.
NotificationsTell an owner, with a link to the failed run.

Expressions to capture the error

result('Try')                                   // status and errors of every action in the scope
workflow()?['run']?['name']                     // this run's ID
utcNow()                                        // timestamp for the log
actions('Action_name')?['error']?['message']    // one action's exact error

Build a run link for the alert from workflow(), so whoever gets the message can open the failed run directly.

Where to log errors

  • A SharePoint list or Dataverse table, for a central error log across flows.
  • Application Insights, for advanced monitoring.
  • Email or Teams, with the run link, so someone acts quickly.

Common mistakes

  • No scopes, so there's nowhere to catch errors.
  • Forgetting run after on the catch steps.
  • No retry on connector and API calls.
  • No notification and no log, so failures go unnoticed.
  • Catching the error and then letting the run show Succeeded. End the Catch with Terminate (Failed).
