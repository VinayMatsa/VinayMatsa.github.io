Split On and trigger batching

VM Vinay Matsa 21 November 2026 3 min read

Some triggers check for new data on a schedule and can find several items at once. With Split On turned on (the default for many triggers), the trigger starts one run per item. With it off, one run receives all the items as an array.

Where it shows up

"splitOn": "@triggerOutputs()?['body/value']"
PieceWhat it does
triggerOutputs()?['body/value']The array of items the trigger found in one check.
splitOnStarts a separate run for each element of that array.

On or off?

Split On (default)Split On off
RunsOne per itemOne per check, with all items
In the flowFields are available directly from the triggerYou loop over triggerBody()?['value']
FailuresOne bad item fails only its own runOne run handles everything; plan error handling per item
Good forMost item-by-item processesBatch work: one summary for everything new, or bulk writes

The setting is in the trigger's Settings. Trigger conditions are evaluated per item when Split On is on, so they filter individual items.

Runs at the same time

With Split On, ten new items can mean ten runs at once. If the runs update the same record or must happen in order, turn on the trigger's Concurrency control and set the degree of parallelism to 1, so runs queue and execute one at a time.

New to this? Start from the basics optional

Polling trigger: a trigger that checks for changes on a schedule (every minute here) rather than being told instantly.

Debatching: another name for splitting an array into separate runs.

Build it step by step optional
  1. Open the trigger's Settings.
  2. Leave Split On on for item-by-item processing, or turn it off to receive all items in one run.
  3. If runs must not overlap, turn on Concurrency control and set it to 1.
  4. Test by creating three items at once and checking run history.

Common mistakes

  • Turning Split On off but still reading fields as if there were one item.
  • Parallel runs updating the same summary record and overwriting each other.
  • Expecting instant starts from a polling trigger. Allow for the polling interval.
