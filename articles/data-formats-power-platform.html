Understanding and debugging data formats in Power Platform

VM Vinay Matsa 12 November 2026 2 min read

When I started with Power Automate, run outputs were full of strange text: VmluYXk=, %2D, \", $content-type. I thought something was broken. Nothing was; each one was data in a different format.

Start from the root

Every value in a flow has a type (text, number, boolean, object, array) and often a format (how that value is written down). The same date can be 2026-11-12T10:00:00Z or 12/11/2026; the same file can be raw bytes or a Base64 string. Most "mystery" errors are a wrong type or a wrong format, not a wrong flow.

What surprised me most

  • Base64 isn't security. It looks scrambled but is fully reversible.
  • "Binary" means file bytes, not literally 0s and 1s on screen.
  • One unencoded & in a URL quietly splits a parameter in two and breaks an API call.
  • Money needs decimal. With floating point, 0.1 + 0.2 isn't exactly 0.3.
  • "Approved" isn't "approved": comparisons are case-sensitive. Use toLower() on both sides.
  • Dates off by 5:30 (in India) means the time zone was never converted.

Four questions before anything else

  1. What type is this value?
  2. What format is it in?
  3. Is it encoded, once or twice?
  4. Which time zone?

Most of the time, the answer to a failed run is in one of them. The Power Automate Learn section on this site covers data types, text functions and dates and time zones in more depth.
