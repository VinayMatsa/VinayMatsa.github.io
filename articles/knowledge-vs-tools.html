Knowledge or tools? How Copilot Studio agents use your data

VM Vinay Matsa 19 October 2026 2 min read

One question I hear a lot: "Should I add this as knowledge or as a tool?" There's a simple rule.

Start from the root

An agent can use your data in two fundamentally different ways. It can read it to answer a question, or it can call something to fetch live data or make a change. Copilot Studio calls the first knowledge and the second tools.

KnowledgeTools
In one wordWhat the agent knowsWhat the agent can do
HowSearches files, sites and tables, and answers with citationsCalls actions: connectors, flows, MCP servers, APIs
Changes data?Never; read-onlyCan create, update, delete, send
Example"What is our leave policy?""Apply leave for Friday."

Which to pick, in order

  1. Fixed documents? Upload them, or point to SharePoint.
  2. Records in Dataverse? Add Dataverse as knowledge.
  3. Live data in another system? Use a real-time connector.
  4. Need an action? Add a tool.
  5. Data behind a firewall? Add the on-premises data gateway.

Numbers worth remembering

At the time of writing (October 2026), Microsoft Learn listed:

  • Up to 500 knowledge sources per agent.
  • Up to 128 tools per agent, with 25 to 30 working best in practice.
  • 512 MB per uploaded file, up to 500 files.
  • SharePoint and OneDrive files synced every 4 to 6 hours.

Limits change, so check the quotas page before designing around them.
