Licensing basics for flows

VM Vinay Matsa 21 November 2026 3 min read

Licensing decides which connectors a flow may use and how many requests it gets each day. A builder should be able to answer: can this flow run on what we have, and who needs a licence? Prices and plan names change, so treat this as orientation.

Is this flow premium?

WhatStandard connectors come with Microsoft 365; premium connectors and features need a standalone licence.
WhyOne premium action makes the whole flow premium, for everyone who needs to run it.
DemoA SharePoint + Teams flow that gains one HTTP action.

Check before you build

Does it use any premium connector (Dataverse, HTTP, SQL Server…), a custom connector, or desktop flows?

Whose licence counts

Flow typeLicence that counts
Automated / scheduledThe owner's
Instant (button, Power Apps)Generally the person who runs it, unless the flow has a Process licence
Serving a licensed Power Apps / Dynamics 365 appCan be covered by that app's licence

AI Builder capacity and desktop flows

AI BuilderLicensed by capacity, not by user. Testing models is free; running them in flows uses credits. Microsoft is ending AI Builder credits: AI features can use Copilot Credits when AI Builder credits run out. Check capacity before production.
Desktop flowsPremium covers attended runs (user signed in). Unattended runs need Process licences or pay-as-you-go.

Common mistakes

  • Building on a trial, then finding users only have Microsoft 365.
  • Adding one HTTP or Dataverse action without noticing.
  • Every production flow under one employee's account (see Ownership and service accounts).
