Custom connectors in Power Platform: why you need them and how to build one

VM Vinay Matsa 7 October 2026 2 min read

Power Automate, Power Apps, Logic Apps and Copilot Studio share over 1,000 prebuilt connectors. But what happens when the API you need isn't one of them?

Start from the root

A connector is a wrapper around a web API that turns its endpoints into actions and triggers makers can drag into a flow or app. Each connector describes the API (its URLs, inputs and outputs) and how to sign in. A custom connector is one you describe yourself, for any REST API. Once built, it looks and behaves like any other connector, and it can be shared and governed by data policies.

The building blocks

BlockWhat it is
ConnectorThe object you create and share in an environment.
DefinitionAn OpenAPI (Swagger) description of the API's operations.
ConnectionA signed-in instance of the connector for a user or service account.
RequestEach action: method, path, parameters and response schema.
CodeOptional C# that transforms requests or responses.

Authentication

Options include no authentication, API key, basic authentication and OAuth 2.0 (including Microsoft Entra ID). Each needs its own parameters, such as the header name for an API key or the client ID, authorisation URL and scope for OAuth.

OpenAPI extensions worth knowing

  • x-ms-visibility: hide or promote parameters in the designer.
  • testConnection: an operation the platform calls to check a connection works.
  • Chunked transfer for large payloads.
  • Dynamic values for drop-down lists filled from the API.

One connector across Dev, Test and Prod

Hosts usually differ per environment. Use an environment variable for the host, or the Set host URL policy, so the same connector definition moves through your solutions unchanged.

Custom code

A C# Script class inheriting ScriptBase implements ExecuteAsync and can call Context.SendAsync to forward the request, letting you reshape requests and responses the API returns awkwardly.

My biggest lesson

"Saved" is not "valid". The portal enforces only some of the documented rules when you save, so follow the documentation, not just what the portal accepts. One of my connectors failed silently; the cause turned out to be a data policy blocking it.
