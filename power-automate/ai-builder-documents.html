AI Builder document processing and human review

VM Vinay Matsa 21 November 2026 3 min read

AI Builder adds ready-made AI to flows. For documents, two kinds of model matter: prebuilt models (invoices, receipts, ID documents, business cards) that work without training, and custom document processing models that you train on your own forms. Both return each field with a confidence score.

The shape of a document flow

  1. A file arrives: an email attachment, a SharePoint upload, a Teams message.
  2. Extract information from invoices (prebuilt) or Extract information from documents (custom model) reads it.
  3. A Condition checks the confidence of the important fields.
  4. High confidence: write the values to a list or system. Low confidence: send to a person to check, with the extracted values pre-filled.

Using confidence

Every extracted field has a value and a confidence between 0 and 1. Pick a threshold per field based on the cost of a mistake (an amount needs more certainty than a reference note).

and(greaterOrEquals(outputs('Extract_information_from_invoices')?['body/responsev2/predictionOutput/invoiceTotal/confidence'], 0.85), not(empty(outputs('Extract_information_from_invoices')?['body/responsev2/predictionOutput/invoiceId/value'])))
PieceWhat it does
predictionOutput/invoiceTotal/confidenceHow sure the model is about the total. Pick the token from dynamic content rather than typing the path.
greaterOrEquals(..., 0.85)The threshold. Start strict and loosen once you've seen real results.
not(empty(.../invoiceId/value))A field that must exist at all, whatever its confidence.

Human review

For the low-confidence branch, a Start and wait for an approval (or an Adaptive Card in Teams) shows the reviewer the file link and the extracted values. The reviewer corrects or confirms, and the flow writes the confirmed values. Keep the original file and the model's output in an audit list, so you can measure how often reviewers change values and retrain the model.

Credits

AI Builder runs on capacity. Testing a model in AI Builder doesn't consume capacity; each run in a flow does, per page. AI Builder credits are being phased out in favour of Copilot Credits, so check your environment's capacity before scaling up. This page has no live demo, because running AI Builder models in a flow uses paid capacity.

New to this? Start from the basics optional

Model: an AI component trained to do one task, such as reading invoices.

Confidence score: the model's own estimate that a value is correct. 0.95 means very sure, 0.40 means a guess.

Human in the loop: a person checks the AI's work before it's used.

Build it step by step optional
  1. In AI Builder, try the prebuilt invoice model on a sample file. If your documents are specific forms, train a custom document processing model with at least five samples per layout.
  2. Build a flow that gets the file content and passes it to the extract action.
  3. Add a Condition on the confidence of the key fields.
  4. In the Yes branch, create the record. In the No branch, start an approval with the extracted values and the file link.
  5. Log every document, its confidences and the reviewer's changes.

Common mistakes

  • Trusting every value because the run succeeded. Success means the model ran, not that it was right.
  • One threshold for all fields.
  • Sending password-protected or very low-resolution scans. The model returns empty values.
