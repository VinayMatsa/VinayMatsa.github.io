Flows for Copilot Studio agents

VM Vinay Matsa 21 November 2026 3 min read

An agent built in Copilot Studio can answer questions from knowledge, but to do something (create a ticket, look up an order, send an approval) it calls a flow. Copilot Studio calls these agent flows. They use the same designer and connectors as cloud flows, with a trigger and a response made for agents.

The shape

  1. Trigger: When an agent calls the flow, with typed inputs (text, number, yes/no).
  2. Your actions: look up, create, update.
  3. Respond to the agent, with typed outputs the agent can use in its reply.

It's the same pattern as calling a flow from Power Apps: typed inputs in, typed outputs back, and the caller waits for the response.

Using the flow in an agent

  • Add the flow to the agent as a tool (action). Give the tool and each input a clear name and description: the agent uses them to decide when to call it and what to pass.
  • Or call it from a topic with an action node, mapping topic variables to inputs and outputs to variables.
  • Return short, useful outputs (a status, an ID, one or two fields). Large tables slow the conversation.

Things to plan for

  • Time. The agent waits for the response, and there is a time limit. Respond quickly; for long work, respond with "started" and send the result later (for example by email or Teams).
  • Whose identity. Connections can use the maker's credentials or the user's. For user-specific data, use the user's, so people only see what they're allowed to.
  • Billing. Agent flows created in Copilot Studio run on Copilot Studio capacity, not on Power Automate per-user licences.
  • ALM. Build them in a solution, with connection references, like any other flow.

Why there's no demo here

The demos in this series stay inside Power Automate. The flow side is the same as the Power Apps demo: swap the trigger and the response for the agent versions.

New to this? Start from the basics optional

Agent: an AI assistant you build in Copilot Studio that people chat with.

Tool: something the agent can use to act, such as a flow, a connector action or a prompt.

Topic: a scripted conversation path inside an agent.

Build it step by step optional
  1. In Copilot Studio, open your agent and add a new tool of type agent flow (or create one from the Flows area).
  2. Define the inputs with clear names and descriptions.
  3. Add the actions, then Respond to the agent with the outputs.
  4. Publish the flow, then test from the agent's test pane with a natural request.
  5. Check the activity map to see which inputs the agent passed.

Common mistakes

  • Vague tool descriptions, so the agent calls the wrong flow or none.
  • Returning raw JSON blobs that the agent then repeats to the user.
  • Running everything as the maker, which can show users data they shouldn't see.
