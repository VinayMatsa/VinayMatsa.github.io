AI Builder document processing and human review

VM Vinay Matsa 21 November 2026 3 min read

AI Builder adds ready-made AI to flows. For documents: prebuilt models (invoices, receipts, IDs) work without training; custom document processing models learn your forms. Both return each field with a confidence score.

The shape of a document flow

WhatExtract fields with a model, then decide per field whether its confidence is high enough.
WhyAI saves typing, but a wrong amount is costly: uncertain values go to a person.
DemoAn invoice: number, supplier, total.

Extract, check, route

A file arrives (email, SharePoint, Teams)
Extract information from invoices
Total confidence ≥ 0.85 and invoice number present?
Yes
Write the values
No

and(greaterOrEquals(outputs('Extract_information_from_invoices')?['body/responsev2/predictionOutput/invoiceTotal/confidence'], 0.85), not(empty(outputs('Extract_information_from_invoices')?['body/responsev2/predictionOutput/invoiceId/value'])))
PieceWhat it does
…/invoiceTotal/confidenceHow sure the model is about the total. Pick the token rather than typing the path.
greaterOrEquals(..., 0.85)The threshold: strict first, loosen with experience.
not(empty(.../invoiceId/value))A field that must exist.

Capacity

Testing a model in AI Builder doesn't use capacity; each run in a flow does, per page. AI Builder credits are being phased out in favour of Copilot Credits. No live demo here, because running models uses paid capacity.

New to this? Start from the basics optional

Confidence score: the model's estimate that a value is correct (0 to 1).

Human in the loop: a person checks AI work before it's used.

Common mistakes

  • Trusting values because the run succeeded.
  • One threshold for every field.
  • Low-resolution or protected scans.
