Split On and trigger batching

VM Vinay Matsa 21 November 2026 3 min read

Some triggers check for changes and find several new items at once. By default, Split On starts one run per item. Sometimes you want one run with all of them.

Where it shows up

WhatA trigger setting that splits an array of new items into separate runs.
WhyIt decides whether you handle items one by one or as a batch, and how failures spread.
DemoA SharePoint trigger that polls every minute.
"splitOn": "@triggerOutputs()?['body/value']"

With Split On, trigger conditions are evaluated per item, so they filter individual items.

Watch out

  • Turning trigger concurrency on can't be undone without re-adding the trigger.
  • With trigger concurrency on, Split On is limited to 100 items.

Common mistakes

  • Expecting one run when ten items arrive at once.
  • Overlapping runs updating the same record.
  • Split On off without per-item error handling.
