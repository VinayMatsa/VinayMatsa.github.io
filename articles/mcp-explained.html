MCP explained: host, client, server and tools, with a Dataverse example

VM Vinay Matsa 16 November 2026 2 min read

Everyone's talking about MCP, but "MCP server", "connector", "tool" and "host" often get mixed up. This article puts them in order.

Start from the root

An AI model on its own can only produce text. To look something up or change something in your systems, it needs a way to call them. Before MCP, every AI app needed its own custom integration for every system: its own sign-in handling, URLs and data formats.

The Model Context Protocol (MCP) is one shared set of rules between AI apps and the systems they use. A useful comparison is USB-C: one shape of plug, so any device fits any charger that follows the standard.

The four parts

PartWhat it isExample
HostThe AI app you use, with an MCP client built inClaude, ChatGPT, Microsoft Copilot, Copilot Studio
MCP clientThe part of the host that talks MCP to a serverBuilt into the host
MCP serverAn adapter in front of one serviceThe Dataverse MCP server, a GitHub MCP server
ToolOne action a server offerscreate_record, list_tables

How one request flows

  1. Discover: the client asks the server which tools it has (tools/list).
  2. Decide: the AI picks a tool. MCP itself doesn't think; the model does.
  3. Call: the client sends tools/call with the inputs.
  4. Act: the server does the work, using your sign-in.
  5. Answer: the result goes back to the AI, and then to you.

Why not just call the APIs?

Every API has its own authentication, URLs and formats. An MCP server wraps the API in one shape that any MCP-enabled app can discover and call. With three AI apps and three systems, direct integration needs nine custom connections; with MCP you build three clients and three servers. MCP doesn't replace APIs: the servers still call them underneath.

A Power Platform example

Ask an MCP-enabled assistant to "add a contact called PVink". The AI picks create_record, and the Dataverse MCP server adds the row to Contacts. Deletes run only after you approve them, and your Dataverse security roles still apply, because the server acts as you.

In Claude Code, you add a server with claude mcp add and check what's connected with /mcp.

Staying safe

  • Use official servers from the vendor of the system.
  • Watch for prompt injection and tool poisoning (a malicious server describing its tools in a way that manipulates the AI).
  • Keep approvals on for actions that change data.
  • Never paste API keys into chats.
