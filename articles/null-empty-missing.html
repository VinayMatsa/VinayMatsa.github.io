Handling null, empty and missing values in Power Automate

VM Vinay Matsa 13 May 2026 2 min read

One of the most common errors in Power Automate is InvalidTemplate ... The provided value is of type 'Null'. Most of these failures aren't flow problems; they're data-handling problems.

Start from the root

StateMeaningExample
NullThe field exists but has no value"phone": null
EmptyA value exists but contains nothing"phone": "" or []
MissingThe property isn't there at allNo phone key in the object
BlankA Power Apps idea, not a flow valueBlank() in a formula

Flow expressions don't validate their inputs. They expect the right type, and fail when a value is missing or null where text or a number was expected.

Common mistakes

  • Using values without checking them.
  • Assuming optional fields always have data.
  • Reading nested fields directly (['a']['b']).
  • Checking only for null and forgetting empty strings.

The result is runtime failures, or worse, silently wrong output.

The three tools

empty(triggerBody()?['phone'])                       // true for null, "" and []
coalesce(triggerBody()?['phone'], 'No phone on file') // first non-null value
triggerBody()?['address']?['city']                    // ? returns null instead of failing
  • empty() safely checks whether there's anything there.
  • coalesce() supplies a default when data is missing.
  • The ? operator reads optional or nested properties without failing.

The golden rule

Check, convert, use. If a field is optional, treat it as unsafe; validate before using it. Small checks prevent big failures. The handling nulls page in the Learn section has a demo flow with real outputs.
