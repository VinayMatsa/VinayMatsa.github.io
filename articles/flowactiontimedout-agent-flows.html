Handling FlowActionTimedOut in Copilot Studio agent flows

VM Vinay Matsa 22 October 2026 2 min read

I added a Copilot Studio agent to my Leave Management lab solution, and the first version failed. The agent flow created the leave request and then waited for the approval to finish.

Start from the root

When an agent uses a flow as a tool, it calls the flow and waits for a response, like a function call. Microsoft Learn states that an agent flow used this way must respond within 100 seconds. An approval can take hours. So a flow that creates a request and then waits for the approver can never answer in time.

Why this is worse than an error message

When the limit passes, the agent returns FlowActionTimedOut, but the flow keeps running in the background. So:

  • The employee sees an error.
  • The leave request may actually have been created.
  • They try again, and now there's a duplicate request.

The design that fixed it

  1. Respond early. The agent flow creates the request and returns a confirmation immediately.
  2. Let Dataverse trigger the approval. A separate flow, triggered when the request row is created, runs the approval. The same logic now serves the canvas app, the model-driven app and the agent.
  3. Notify asynchronously. When the approval finishes, the employee gets the decision by email.
  4. Prevent duplicates. Don't rely on the agent's error. Use a request ID, status checks or duplicate checks so a retry can't create a second request.
  5. Use the signed-in identity. The agent finds the employee's email from their sign-in, never from an address typed into the chat.

What changed

  • Agent response time: about 0.9 seconds, with no more timeouts.
  • One shared approval process across three experiences.
  • The agent no longer waits for long-running work.
The lesson: moving logic into Power Automate doesn't fix a timeout if the agent still waits for it. Let the agent respond quickly and let long-running processes run on their own.
