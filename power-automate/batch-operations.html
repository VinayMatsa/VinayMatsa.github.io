Batch operations and changesets

VM Vinay Matsa 21 November 2026 3 min read

When a flow writes many rows, the usual pattern is a loop with one Create or Update per item: one request and one round trip each. Batching sends several operations in one call; changesets make a group of writes all or nothing.

Ways to reduce write calls

WhatTechniques that cut the number of write requests, or make a group of writes one transaction.
WhyFewer calls means faster runs and fewer requests; transactions keep related data consistent.

New to this? Start from the basics optional

Batch: many operations in one call; each can still succeed or fail on its own.

Transaction / rollback: changes saved together or not at all.

Common mistakes

  • Expecting a batch to roll back. Only a changeset does.
  • Concurrency on writes that depend on each other.
  • Referencing a row created earlier in the same changeset.
