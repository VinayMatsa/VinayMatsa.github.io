Fixing the Dataverse lookup error in Power Automate

VM Vinay Matsa 9 October 2026 2 min read

Ever hit BadRequest: ODataUnrecognizedPathException with "Resource not found for the segment"? In my run, List rows and Get a row by ID both worked with a GUID, and only Update a row failed.

Start from the root

Every Dataverse row has a GUID, a unique ID like 3f2b...-.... A lookup column is a column that points to a row in another table: a Case's Customer points to a Contact, for example.

Two different jobs use GUIDs:

  • Identifying a row (Row ID in Get, Update, Delete): a plain GUID is right.
  • Linking to a row (setting a lookup): Dataverse needs to know which table the GUID belongs to, so it expects a path like /contacts(GUID).

Passing a plain GUID into a lookup column is what triggers the error.

The fix

  1. Find the related row's GUID, for example with List rows.
  2. Wrap it in the table's path with concat().
  3. Put that into the lookup column in Update a row (or Add a new row).
concat('/contacts(', first(outputs('List_rows')?['body/value'])?['contactid'], ')')
PieceWhat it does
'/contacts('The entity set name (plural, lowercase) of the target table.
first(...)?['contactid']The GUID of the first row found.
')'Closes the path.

Remember

  • Keep Row ID as a plain GUID; only lookup columns need the table path.
  • Identifying a record = GUID. Linking a record = /table(GUID).
  • Use the entity set name (for example contacts, accounts), not the display name.
