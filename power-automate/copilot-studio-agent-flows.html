Flows for Copilot Studio agents

VM Vinay Matsa 21 November 2026 3 min read

A Copilot Studio agent answers from knowledge, but to do something (create a ticket, look up an order, start an approval) it calls a flow: an agent flow.

Agent → flow → agent

WhatA flow with When an agent calls the flow and Respond to the agent, used by the agent as a tool.
WhyAgents can act on business data, not just talk about it.
Demo“Apply leave for Friday” → the agent calls a flow and confirms.

One tool call

User asks the agent
Agent picks the tool by its name and description
Flow trigger: typed inputs
Actions: look up, create, update
Respond to the agent: typed outputs
Agent replies using the outputs

Plan for these

TopicWhat to do
TimeThe agent waits and there's a time limit: respond quickly; send long results later (email, Teams)
IdentityUse the user's credentials for user-specific data
BillingAgent flows created in Copilot Studio use Copilot Studio capacity
ALMBuild in a solution with connection references
OutputsShort and useful: a status, an ID, a field or two

Long work without timing out

Agent calls the flow
Create the record, respond “started” at once
A separate flow (e.g. triggered by the new row) does the slow work
Notify the user when done
New to this? Start from the basics optional

Tool: something an agent can use to act: a flow, connector action or prompt.

Topic: a scripted conversation path inside an agent.

Build it step by step optional
  1. In Copilot Studio, add a tool of type agent flow.
  2. Define inputs with clear names and descriptions.
  3. Add actions, then Respond to the agent.
  4. Publish and test in the test pane; check the activity map.

Common mistakes

  • Vague tool descriptions.
  • Raw JSON returned to the agent.
  • Everything running as the maker.
