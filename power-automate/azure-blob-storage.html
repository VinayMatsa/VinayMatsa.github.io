Azure Blob Storage for files

VM Vinay Matsa 21 November 2026 3 min read

Azure Blob Storage is cheap, large-scale file storage in Azure. Flows use it to archive attachments, keep exports that are too big or too many for SharePoint, and hand files to other systems. The connector is premium and needs an Azure subscription, so there's no live demo here.

How Blob Storage is organised

TermMeaning
Storage accountThe top-level resource, with its own name and access settings.
ContainerA folder-like group of blobs inside the account. Access rules apply per container.
BlobOne file. Its name can include slashes (2026/11/invoice-2048.pdf), which shows up as virtual folders.

The actions

  • Create blob (V2): write file content to a path. Common source: an email attachment's Content Bytes (decode with base64ToBinary()) or a SharePoint file's content.
  • Get blob content (V2) and Get blob content using path (V2): read a file.
  • Lists blobs (V2): what's in a folder, with paging.
  • Create SAS URI by path (V2): a time-limited link that lets someone download one blob without an account.
  • Trigger When a blob is added or modified (properties only) (V2): react to new files.
concat('archive/', formatDateTime(utcNow(), 'yyyy/MM'), '/', items('Apply_to_each')?['Name'])
PieceWhat it does
'archive/'Top-level virtual folder.
formatDateTime(utcNow(), 'yyyy/MM')Year and month folders, so the container stays browsable.
items(...)?['Name']The attachment's file name.

Access

Prefer Microsoft Entra ID authentication on the connection, with the account given the Storage Blob Data Contributor role on just the containers it needs. Avoid account access keys in connections: a key opens the whole storage account.

New to this? Start from the basics optional

Azure subscription: the billing account for Azure resources. Blob Storage is billed by stored data and operations.

SAS (shared access signature): a signed link with an expiry time and limited permissions.

Build it step by step optional
  1. Create a storage account and a container (or ask your Azure admin to).
  2. Grant the flow's account a data role on the container.
  3. Create an Azure Blob Storage connection with Microsoft Entra ID authentication.
  4. Add Create blob (V2) with a folder path built from the date and the file name.
  5. Share files with Create SAS URI by path (V2) and a short expiry, not by making the container public.

Common mistakes

  • Writing every file to the container root. Use dated paths.
  • Public containers for convenience.
  • Same file name every run, which silently overwrites the earlier blob.
